# 자기지도학습 — 라벨링 병목을 어떻게 뚫었나

## 한눈에 보기
| 항목 | 핵심 |
|------|------|
| 막고 있던 것 | 사람이 라벨을 붙여야 해서 데이터가 돈만큼만 늘어난다 |
| 뚫은 방법 | 정답을 데이터 자체에서 뽑아낸다 |
| 왜 언어 모델이었나 | "다음 토큰"이라는 정답이 문장 안에 이미 들어 있다 |
| 결과 | 인터넷의 모든 글이 학습 데이터가 되고, 모델이 LLM 규모로 커졌다 |
| 헷갈림 주의 | 자기지도 ≠ 비지도 |

## 1. 왜 이게 필요한가

### 이런 상황을 상상해 보자
2012년 딥러닝 혁명을 연 AlexNet은 ImageNet이라는 데이터셋으로 학습했다. 이미지 100만 장을
"자동차"·"풍선"·"원숭이" 같은 1,000개 범주 중 하나로 분류하는 과제였다.

이 100만 장에는 사람이 하나씩 손으로 정답을 달아야 했다. 한 장에 5센트라고 치자.

```text
이미지 100만 장 × 5센트                   =    $50,000
품질 교차검증하려고 2명이 각각 라벨링      =   $100,000
```

### 여기서 뭐가 무너지나
문제는 이 비용이 **범주 수에 따라 같이 커진다**는 데 있다. 세상에는 1,000가지보다 훨씬 많은 사물이 있으니,
더 많은 것을 알아보게 하려면 범주를 늘려야 한다.

```text
1,000개 범주   →  $50,000
100만 개 범주  →  $50,000,000
```

게다가 모든 라벨링이 똑같이 싼 것도 아니다. 일상 사물에 이름 붙이기는 아무나 할 수 있어 싸지만,
영어→라틴어 번역문을 만드는 일은 훨씬 비싸고, CT 사진에 암 징후가 있는지 판정하는 일은 천문학적이다.

즉 이 방식에서 데이터의 양은 **쓸 수 있는 돈만큼만** 늘어난다. 모델을 키우려면 데이터가 더 필요한데,
데이터는 돈에 묶여 있다. 여기가 병목이다.

### 그래서 나온 생각
사람이 정답표를 새로 만드는 대신, **데이터 안에 이미 들어 있는 정답을 꺼내 쓰면** 어떨까.

"나는 길거리 음식을 좋아한다"라는 문장 하나를 보자. 이 문장에는 아무도 라벨을 붙이지 않았다.
그런데 앞부분을 보여주고 다음 단어를 맞히게 하면, 정답은 이미 문장 안에 있다.
문장 하나가 학습 샘플 여러 개를 스스로 만들어낸다.

이렇게 **입력 데이터 자체에서 정답을 뽑아내 학습하는 방식**이 **[[자기지도학습]]**이다.
사람이 라벨을 붙여주는 기존 방식은 **[[지도학습]]**(= 사람이 붙인 정답표로 학습시키는 방식)이라 부른다.
"지도(supervision)"란 정답표를 뜻하고, "자기(self)"는 그 정답표를 남이 아니라 데이터 자신이 준다는 뜻이다 —
이름이 그대로 구조를 말해준다.

쉽게 말하면 영어 단어장 오른쪽 뜻을 손으로 가리고 맞히는 것과 같다. 정답은 이미 종이에 인쇄돼 있고,
나는 가리기만 하면 된다.

→ 비유가 깨지는 지점: 단어장은 누군가 학습용으로 "단어–뜻" 쌍을 일부러 만들어 둔 것이다.
자기지도학습이 먹는 글은 그렇지 않다 — 블로그 글도 레딧 댓글도 학습용으로 쓰인 게 아닌데,
가리기만 하면 그대로 학습 샘플이 된다. 그래서 "만들어진 문제집을 푸는 것"이 아니라
**세상의 모든 글이 저절로 문제집이 되는 것**이다. 규모의 차이가 여기서 갈린다.

## 2. 어떻게 동작하는가

"나는 길거리 음식을 좋아한다"에 해당하는 영어 문장 `I love street food.` 하나로 학습 샘플을 만들어 보자.

1. **경계 표시 붙이기**: 문장 앞뒤에 `<BOS>`(시작)와 `<EOS>`(끝) 표시를 특별한 토큰으로 붙인다 —
   여러 문장을 이어 다룰 때 어디서 시작하고 끝나는지 모델이 알아야 하기 때문이다.
   특히 `<EOS>`가 중요하다. 이게 없으면 모델은 답을 언제 멈춰야 할지 알 수 없다.
2. **잘라가며 쌍 만들기**: 앞에서부터 한 토큰씩 늘려가며 (지금까지의 문맥 → 다음 토큰) 쌍을 만든다 —
   한 문장에서 최대한 많은 학습 신호를 뽑아내기 위해서다.
3. **예측 → 비교 → 갱신**: 모델이 다음 토큰을 예측하고, 실제 토큰과 비교해 틀린 만큼 내부 변수 값을 고친다.
   이 "학습 과정에서 갱신되는 내부 변수"가 **[[파라미터]]**(= 모델 안에서 학습으로 값이 바뀌는 변수)다 —
   모델이 배운 것이 저장되는 곳이 여기라서, 여기를 고치는 것이 곧 학습이다.
4. **모든 글에 반복**: 라벨링 비용이 0이므로 책·블로그·기사·댓글, 글이 있는 곳이면 어디든 1~3을 돌린다 —
   이 단계가 가능해진 것이 규모(scale)의 정체다.

**모델의 크기를 잰다**는 말은 보통 [[파라미터]] 개수를 센다는 뜻이다.
원래 파라미터는 가중치와 편향(bias)을 합친 것이지만, 오늘날은 그냥 **[[가중치]]**라는 말로 전체를 가리킨다.

```text
2018.06  GPT-1     1.17억 개   ← 당시엔 "크다"
2019.02  GPT-2     15억 개     ← 1.17억이 갑자기 "작다"가 됨
2024     ~         1,000억 개  ← 지금의 "크다". 내일은 작을 것이다
```

`LLM`의 `L`(large)이 과학적인 기준이 아닌 이유가 이것이다 — 오늘의 "크다"가 내일의 "작다"다.

**왜 큰 모델은 데이터가 더 필요한가.** 직관에 반해 보인다. 똑똑하면 적게 봐도 배워야 하지 않나?
방향이 다르다. 우리는 큰 모델이 작은 모델의 성능을 *따라잡게* 하려는 게 아니라 **성능을 최대로 끌어올리려는**
것이다. 배울 용량이 크니 그 용량을 채울 만큼 데이터가 있어야 한다. 작은 데이터로 큰 모델을 학습시킬 수는
있지만, 그건 연산 낭비다 — 같은 데이터로 작은 모델을 썼어도 비슷하거나 더 나은 결과가 나왔을 것이다.

## 3. 그림으로 보기

```text
[지도학습 — 사람이 정답표를 만든다]

  이미지 100만 장  ──▶  사람이 하나씩 라벨링  ──▶  (이미지, "고양이")
                          💰 장당 5센트                     학습 샘플
                          ↑
                   여기가 병목. 데이터 양 = 예산에 비례


[자기지도학습 — 데이터가 정답표를 겸한다]

  "I love street food."   ← 아무도 라벨을 붙이지 않은 그냥 문장

        가리고 맞히기 (비용 0)
                ↓
  ┌──────────────────────────────────┬──────────────┐
  │ 입력 (문맥)                       │ 출력(정답)   │
  ├──────────────────────────────────┼──────────────┤
  │ <BOS>                            │ I            │
  │ <BOS>, I                         │ love         │
  │ <BOS>, I, love                   │ street       │
  │ <BOS>, I, love, street           │ food         │
  │ <BOS>, I, love, street, food     │ .            │
  │ <BOS>, I, love, street, food, .  │ <EOS>        │
  └──────────────────────────────────┴──────────────┘
        문장 1개 → 학습 샘플 6개, 사람 손 0번

  ▶ 병목이 "예산"에서 "세상에 남은 글의 양"으로 옮겨갔다.
    이 책 서두가 "공개된 인터넷 데이터가 고갈될 위험"을 말하는 이유가 이것이다.
```

## 4. 이 노트에 나온 용어
| 용어 | 한 줄 | 자세히 |
|------|-------|--------|
| 지도학습 | 사람이 붙인 정답표(라벨)로 학습시키는 방식 | [[_glossary#지도학습]] |
| 자기지도학습 | 정답을 입력 데이터 자체에서 뽑아 학습하는 방식 | [[_glossary#자기지도학습]] |
| 비지도학습 | 라벨이라는 개념 자체가 없는 학습 방식 | [[_glossary#비지도학습]] |
| 파라미터 | 학습으로 값이 갱신되는 모델 내부 변수. 모델 크기의 척도 | [[_glossary#파라미터]] |
| 가중치 | 오늘날 파라미터 전체를 가리키는 말 | [[_glossary#가중치]] |

## 5. 자주 헷갈리는 것
- **자기지도 vs 비지도** — 가장 흔한 혼동이다. **[[비지도학습]]**(= 라벨이 아예 필요 없는 학습)은 라벨이라는
  개념 자체가 없다(예: 군집화). 자기지도학습은 라벨이 **있다** — 다만 사람이 아니라 데이터에서 나올 뿐이다.
  구분 테스트: "이 학습에 정답이 존재하는가?" 자기지도는 예, 비지도는 아니오.
- **"크다"는 절대 기준이 아니다** — LLM의 "large"에는 고정된 파라미터 수 기준이 없다. 시점에 상대적이다.

## 6. 언제 안 쓰나 / 경계
- **모든 과제가 자기지도로 바뀌지는 않는다.** 데이터 안에 정답이 이미 들어 있어야 성립한다. 글에는
  "다음 단어"가 들어 있지만, CT 사진 안에는 "암 여부"가 들어 있지 않다. 그런 과제는 여전히 사람이 라벨을 단다.
- **데이터가 무한하지 않다.** 라벨링 비용이 사라지자 이번엔 원본 글의 총량이 한계로 떠올랐다.
  합성 데이터가 왜 연구 주제가 되었는지가 여기서 나온다.
- **큰 모델 + 작은 데이터는 낭비다.** 가능하긴 하지만 같은 결과를 작은 모델로 더 싸게 낼 수 있다.

## 7. 연결
- [[language-model]] — 언어 모델의 "다음 토큰 맞히기"라는 과제 형태가 자기지도를 가능하게 한 조건이다. 과제 형태가 학습 방식을 결정한 사례.
- [[foundation-model]] — 자기지도는 글에만 쓰이지 않는다. (이미지, 설명글) 쌍을 그대로 학습 신호로 쓰는 자연어 지도가 멀티모달로 가는 문을 열었다.
- [[ai-engineering]] — 자기지도로 모델을 키우려면 소수의 조직만 감당할 수 있는 자원이 든다. 그 비대칭이 "모델을 만드는 쪽"과 "쓰는 쪽"을 갈랐다.

## 8. 스스로 확인
1. 자기지도학습이 없었다면 왜 LLM이 지금 규모까지 커질 수 없었는가? 비용 계산으로 답해 보라.
2. 자기지도와 비지도를 한 문장으로 구분하라. 각각의 예를 하나씩 들라.
3. 언어 모델링은 자기지도가 되는데 암 진단 모델은 왜 안 되는가?
4. "더 큰 모델은 더 많은 데이터가 필요하다"가 직관에 반해 보이는 이유는 무엇이고, 왜 실제로는 반하지 않는가?
