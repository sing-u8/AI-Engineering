# 01. 평가의 난제와 언어 모델링 지표 (PPL, Loss, BPB)

## 📌 핵심 요약 & 전체 맥락
> **"평가(Evaluation)야말로 여러분에게 필요한 전부일 때가 놀라울 정도로 많다."** (OpenAI 공동창업자 그렉 브록만)  
> 파운데이션 모델은 단 하나의 정답(Ground Truth)이 존재하지 않는 **'열린 결말(Open-ended)'**의 특성을 가지며, 모델이 똑똑해질수록 채점 난이도가 기하급수적으로 상승합니다. 현업에서는 종종 '입소문'이나 대충 훑어보는 '바이브 체크(Vibe Check)'에 의존하지만, 프로덕션 성공을 위해서는 전체 시스템 관점의 체계적인 평가가 필수적입니다.  
> 특히 파운데이션 모델의 뿌리인 언어 모델(LM)의 기본 지표인 **크로스 엔트로피(Cross-Entropy)**와 **퍼플렉시티(Perplexity / 당혹도)**는 모델의 불확실성을 측정하고 **데이터 오염(Contamination)**을 탐지하는 핵심 잣대 역할을 합니다.

## 1. 파운데이션 모델 평가가 극도로 어려운 5가지 이유 (pp. 113 ~ 118)

### 💡 저자의 핵심 철학: "평가는 고립된 채점이 아니라 시스템 설계의 문제다" (p. 113)
평가는 단순히 모델 출력을 보고 점수를 매기는 고립된 작업이 아닙니다. **"시스템의 어느 지점에서 장애(Failure)가 발생하기 쉬운지 식별하고, 장애의 가시성(Visibility)을 확보하기 위해 전체 아키텍처를 재설계하는 시스템 엔지니어링 관점"**에서 접근해야 합니다.

---

### [전통적 ML vs 생성형 파운데이션 모델 평가의 5대 난제]

```
[ 파운데이션 모델 평가의 5대 난제 ]

1. 지능 상승에 따른 채점 난이도 폭증 (PhD급 수학/코딩을 누가 채점하는가?)
2. 정답 부재 (Open-endedness: 하나의 질문에 수천 가지 정답 존재)
3. 블랙박스 모델 (가중치와 학습 데이터를 모르는 상태에서의 평가)
4. 벤치마크의 급격한 포화 (시험지가 너무 빨리 만점화됨: MMLU ➔ MMLU-Pro)
5. 평가 범위의 무한 확장 (미지의 능력과 새로운 위험을 탐색해야 함)
```

#### ① 모델이 똑똑해질수록 채점 난이도가 기하급수적으로 상승함
* 초등학교 1학년의 산수 숙제는 누구나 틀린 곳을 찾아낼 수 있지만, **박사(PhD) 수준의 첨단 수학/물리 증명은 세계적인 석학들조차 검증하는 데 수일이 걸립니다.**
* **테렌스 타오 교수의 일화 (Footnote 4):** 필즈상 수상자인 테렌스 타오(Terrence Tao)는 OpenAI의 `o1` 모델을 써보고 *"어설프지만 무능하지는 않은 대학원생 수준"*이라 평가했습니다. 앞으로 AI가 전문 연구자 수준을 넘어서면 **인간 중에 AI를 제대로 채점할 자격을 갖춘 사람이 없어지는 역설**이 발생합니다.
* 긴 책 요약본도 헛소리가 섞여 있는지 채점하려면, 평가자가 먼저 그 두꺼운 책을 전부 읽고 팩트체크해야 합니다.

#### ② 정답(Ground Truth)의 부재: 열린 결말 (Open-endedness)
* "이메일 초안을 작성해줘"라는 요청에는 완벽한 단 하나의 모범 답안이 존재하지 않습니다. 표현, 어조, 길이에 따라 수천 가지의 훌륭한 정답이 존재하므로, 단순 텍스트 일치율로 점수를 매길 수 없습니다.

#### ③ 블랙박스(Black Box) 접근
* 상용 모델(OpenAI, Anthropic 등)은 모델 아키텍처, 파라미터 가중치, 사전 학습 데이터셋을 일체 공개하지 않습니다. 엔지니어는 내부 구조를 모른 채 오직 **'겉으로 드러나는 입출력 반응'**만 보고 모델을 역공학적으로 평가해야 합니다.

#### ④ 벤치마크의 빠른 포화와 도메인 특화 평가 (Benchmark Saturation)
* AI 성능이 너무 빠르게 진화하여, 범용 지식을 묻는 표준 시험지가 1~2년 만에 만점자가 속출하며 쓸모없어집니다.
  * **GLUE (2018) ➔ SuperGLUE (2019)**
  * **MMLU (2020):** 모델들이 90점을 넘기며 변별력 상실 ➔ **MMLU-Pro (2024)**로 고난도 개편
* **실무형 도메인 벤치마크의 부상:** 모델의 진짜 지능을 평가하기 위해 단순 객관식(MMLU)을 넘어 **코드 생성(HumanEval)**과 **수학적 추론(GSM8K, MATH)** 벤치마크가 핵심 잣대로 자리 잡았습니다.
  * **HumanEval (코드):** `pass@k` 지표를 사용합니다. 모델이 $k$개의 코드를 생성해서 한 번이라도 유닛 테스트를 통과하면 정답으로 인정합니다 (예: pass@1, pass@10).
  * **GSM8K / MATH (수학):** 초등수학(GSM8K)과 경시대회(MATH) 문제를 다루며, 단순 정답 매칭이 아닌 풀이 과정(CoT)의 논리성을 평가합니다.

#### ⑤ 현업의 위험한 관행: "바이브 체크(Vibe Check)"의 함정
* a16z의 2023년 조사에 따르면, AI 도입 기업 의사결정자 70명 중 6명은 단순히 **'입소문(Word of mouth)'**에 의존해 모델을 골랐습니다.
* 많은 개발팀이 몇 가지 임의의 프롬프트를 넣어보고 느낌상 잘 나오는 것 같으면 배포하는 **'눈대중 검증(Eyeballing / Vibe Check)'**에 머물러 있습니다. 이는 프로덕션 환경에서 예측 불가능한 장애와 환각을 유발하는 시한폭탄입니다.

> 📖 **도표 참고:**
> * **[Figure 3-1 (p. 116)]**: 2023년 상반기 동안 LLM 평가 논문이 월 2편에서 월 35편으로 폭발적으로 증가한 추세를 보여주는 그래프.
> * **[Figure 3-2 & 3-3 (pp. 117-118)]**: 평가의 중요성에도 불구하고, GitHub 상위 1,000개 저장소 중 평가 도구는 모델링/오케스트레이션 도구에 비해 여전히 인프라 투자가 턱없이 부족함을 증명하는 데이터 (DeepMind 및 Anthropic의 체계적 평가 투자 촉구).

## 2. 언어 모델링 지표: 정보이론 4총사의 수학적 원리 (pp. 118 ~ 122)

파운데이션 모델은 기본적으로 **언어 모델(Language Model)**을 두뇌로 사용합니다. 따라서 1951년 정보이론의 아버지 **클로드 섀넌(Claude Shannon)**의 연구에서 출발한 고전적 언어 모델 지표들을 이해하는 것은 모델의 기초 체력을 평가하는 필수 단계입니다.

> 💡 **비텍스트(Non-text) 확장성:**  
> 이 지표들은 텍스트뿐만 아니라 **오디오 토큰, 이미지 패치, 생체 분자 시퀀스 등 토큰의 연속을 생성하는 모든 생성 모델에 동일하게 적용**됩니다.

```
[ 정보이론 기반 언어 모델 지표 4총사 ]

1. 엔트로피 H(P)          : 데이터가 가진 정보량의 크기 (불확실성)
2. 교차 엔트로피 H(P, Q)   : 모델(Q)이 실제 데이터(P)를 예측하는 난이도 (Loss)
3. 퍼플렉시티 (PPL)        : 모델이 다음 단어를 고를 때 헷갈려하는 선택지의 개수 (2^H 또는 e^H)
4. BPB / BPC             : 바이트/문자당 필요한 비트 수 (텍스트 압축률 척도)
```

---

### ① 엔트로피 (Entropy, $H(P)$): 정보량과 예측 난이도
* **정의:** 어떤 언어나 데이터에서 토큰(글자/단어) 하나가 **평균적으로 담고 있는 정보의 양(Information Content)**.
* **직관적 원리:**
  * 정보량이 많은 언어일수록 한 글자를 컴퓨터 비트(Bits)로 표현하는 데 더 많은 용량이 필요하고, 다음에 올 내용을 예측하기 어렵습니다.
  * 만약 상대방이 다음에 할 말을 100% 예측할 수 있다면, 그 말은 새로운 정보가 전혀 없는 것($\text{Entropy} = 0$)입니다.

```
[ Figure 3-4 시각화: 사각형 내 위치를 나타내는 두 언어의 엔트로피 비교 ]

(a) 2개 토큰 언어 [위 / 아래]                (b) 4개 토큰 언어 [좌상 / 우상 / 좌하 / 우하]
┌──────────────┐                            ┌──────┬──────┐
│      위      │ (1 bit 필요)                │ 좌상 │ 우상 │ (2 bits 필요)
├──────────────┤                            ├──────┼──────┤
│     아래     │ ➔ 엔트로피 = 1               │ 좌하 │ 우하 │ ➔ 엔트로피 = 2
└──────────────┘                            └──────┴──────┘
  (예측 쉬움 / 정보량 적음)                    (예측 어려움 / 정보량 2배)
```

> 📖 **도표 참고:**
> * **[Figure 3-4 (p. 120)]**: 사각형 내 위치를 2개 단어로 표현할 때는 1비트($H=1$)면 충분하지만, 4개 단어로 정밀하게 표현할 때는 2비트($H=2$)가 필요함을 보여주는 시각 자료.

---

### ② 교차 엔트로피 (Cross-Entropy, $H(P, Q)$): 모델의 손실(Loss)
* **정의:** 학습 데이터의 진짜 확률 분포를 $P$, 언어 모델이 학습하여 근사한 분포를 $Q$라고 할 때, **"모델 $Q$를 사용해 실제 데이터 $P$를 예측하고 인코딩할 때 필요한 평균 비트 수"**.
* **수학적 분해:**
$$H(P, Q) = -\sum_{x} P(x) \log Q(x) = H(P) + D_{KL}(P \parallel Q)$$
  * $H(P)$: 데이터 자체의 본질적인 엔트로피 (물리적으로 줄일 수 없는 최소 한계치).
  * $D_{KL}(P \parallel Q)$: **쿨백-라이블러 발산(KL Divergence)**으로, 모델의 분포 $Q$가 실제 분포 $P$와 얼마나 빗나가 있는지를 나타내는 모델의 예측 오차.
* 💡 **심화 부록:** [[05-deep-dive-cross-entropy-loss-and-information-theory|05. [심화] 교차 엔트로피가 모델의 손실(Loss)인 이유와 NLL 벌점 체계]]

---

### ③ 단위의 혼란: Bits vs Nats (Footnote 8)
* **Bits (밑이 2인 로그):** 정보이론 표준 단위.
* **Nats (밑이 $e$인 자연로그 $\ln$):** PyTorch, TensorFlow 등 딥러닝 프레임워크의 기본 단위 ($\ln(x)$의 미분이 $1/x$로 수학 연산이 편리하기 때문).
* 💡 **업계의 해결책:** 논문마다 Bits와 Nats를 혼용하여 생기는 혼란을 피하기 위해, **대부분의 연구진은 크로스 엔트로피 대신 이를 지수화한 '퍼플렉시티(PPL)'로 통일하여 성능을 보고**합니다.

---

### ④ BPC (Bits per Character)와 BPB (Bits per Byte)
* 교차 엔트로피를 글자(Character) 단위나 바이트(Byte) 단위로 환산한 지표.
* **구체적 계산 예시 (p. 121):**
  * 만약 어떤 언어 모델의 $\text{BPC} = 3$이고, 글자 하나가 7비트($\frac{7}{8}$ 바이트)라면:
$$\text{BPB} = \frac{3}{7/8} = 3.43 \text{ bits}$$
* **텍스트 압축기(Compressor)로서의 LLM:**
  * $\text{BPB} = 3.43$이라는 것은, 원래 8비트(1바이트)짜리 텍스트 데이터를 단 3.43비트로 압축하여 저장할 수 있다는 뜻이며, **원본 크기를 절반 이하(약 43%)로 압축**할 수 있음을 의미합니다.

## 3. 퍼플렉시티 (Perplexity, PPL): 모델의 당혹도 (pp. 121 ~ 124)

### ① 퍼플렉시티(PPL)의 본질적 의미
* **정의:** 교차 엔트로피(Cross-Entropy)의 지수승(Exponential).
$$\text{PPL}(P, Q) = 2^{H(P, Q)} \quad (\text{Bits 기준}) \quad \text{또는} \quad e^{H(P, Q)} \quad (\text{Nats 기준})$$
* **직관적 해석:**  
  **"모델이 다음 단어를 예측할 때, 몇 개의 동등한 선택지를 두고 헷갈려(당황해) 하는가?"**
  * 크로스 엔트로피가 $2\text{ bits}$라면 $\text{PPL} = 2^2 = 4$입니다. 즉, 모델은 **"4지선다 문제 앞에서 갈팡질팡하는 상태"**입니다.
  * $\text{PPL} = 1.0$이면 다음 단어를 100% 확신하며 완벽히 맞히는 상태입니다.

---

### ② PPL을 해석하는 3대 황금률 (pp. 123)

```
[ PPL 해석의 3대 황금률 ]

1. 데이터가 구조화(Structured)될수록 PPL은 낮아진다.
   - 일상 대화보다 문법이 엄격한 HTML/코드(<head> 뒤엔 </head>)가 훨씬 예측하기 쉬움.

2. 어휘 사전(Vocabulary)이 커질수록 PPL은 높아진다.
   - 단어 후보가 많을수록 맞히기 어려움 (어린이 동화책 PPL < 《전쟁과 평화》 PPL).

3. 컨텍스트 길이(Context Length)가 길어질수록 PPL은 낮아진다.
   - 섀넌(1951)은 10개 단어만 봤지만, 현대 LLM은 500~10,000개 이상의 문맥을 참조하여 불확실성을 대폭 낮춤.
```

> **💡 PPL 3 이하의 경이로움:**  
> 최신 LLM의 단어장은 **32,000개 ~ 128,000개**에 달합니다. 이렇게 방대한 후보 중에서 모델의 PPL이 **`3`**이라는 것은, 수십만 개 단어 중 **단 3개의 유력 후보 안으로 선택지를 좁혀서 다음 단어를 정확히 맞힌다는 경이적인 예측력**을 뜻합니다.

OpenAI의 GPT-2 연구에 따르면, 모델 파라미터 크기가 커질수록(117M ➔ 1542M) 다양한 벤치마크 데이터셋에서 **PPL이 일관되게 단조 감소(성능 향상)**했습니다.

## 4. 엔지니어링 실무에서의 PPL 활용 및 한계점 (p. 124)

### ① 실무 활용 3대 분야
1. **데이터 오염(Data Contamination) 탐지 ⭐:**
   * 공개 벤치마크 시험지를 모델에 넣었을 때 **PPL이 비정상적으로 극단적인 저점**을 기록한다면, 시험 문제와 정답이 사전 학습 데이터에 통째로 크롤링되어 **문제를 통째로 외웠다(오염되었다)**는 강력한 증거가 됩니다.
2. **학습 데이터 중복 제거(Deduplication):**
   * 새 데이터를 추가할 때 모델의 PPL을 측정하여, 이미 잘 예측하는 데이터(낮은 PPL)는 버리고 **모델에게 생소하고 새로운 정보(높은 PPL)만 선별하여 학습셋에 추가**합니다.
3. **비정상 텍스트 / 헛소리 탐지:**
   * `"우리 집 강아지는 여가 시간에 양자역학을 가르친다"` 같은 기괴한 문장이나 횡설수설 텍스트는 PPL이 치솟으므로, 데이터 정제 필터로 활용할 수 있습니다.

---

### ② PPL의 치명적 한계: SFT 및 RLHF 이후의 왜곡 ⚠️

> ⚠️ **포스트 트레이닝(Post-training) 후 PPL 사용 주의 (Footnote 9)**
> * SFT(지도 미세조정)나 RLHF(선호도 미세조정)를 거친 모델은 **"특정 지시를 따르고 태스크를 완수하는 법"**을 배웁니다.
> * 이 과정에서 일반적인 다음 단어 예측 분포가 왜곡되며 **'엔트로피 붕괴(Entropy Collapse)'**가 일어나, **실제 대화 성능은 훨씬 좋아졌음에도 PPL 수치는 오히려 증가(악화)**하는 현상이 빈번히 발생합니다.
> * 또한 **양자화(Quantization, Footnote 10)**를 적용할 때도 수치 정밀도 감소로 인해 PPL이 비선형적으로 요동치므로, 사후 학습된 상용 챗봇 모델을 순수 PPL만으로 비교하는 것은 위험합니다.
